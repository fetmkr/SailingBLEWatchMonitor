# firmware-idf 이사 체크리스트

**이 표에 없는 일은 하지 않는다. 이 표에서 칸을 채우는 것만 한다.**
만든 날 2026-09-15 저녁. 사용자: "왜 지금 마이그레이션하는거 트래킹안해? 목적없이하는거야? 체크리스트 만들어서 해야할거 아니야."
결과·실측값의 자세한 기록은 `PORTING.md`. 여기에는 **판정과 증거 위치**만 적는다.

---

## 1. 목적 — 왜 옮기나

1. **WiFi 로 SD 파일 받는 속도를 올린다.** firmware-rak 은 241 kb/s 로 느렸다 (사용자 실측). 아두이노 코어 2.0.17 은 TCP 창 5,760 이 미리 빌드돼 못 바꾼다 (NEXT.md 11). IDF 에서는 바꿀 수 있다.
2. 그러면서 **firmware-rak 이 보드에서 하던 일을 하나도 잃지 않는다.** 기준은 REQUIREMENTS.md 의 보드 칸 ✅ 전부.

목적 1 을 재지 않은 채 "이사 끝" 이라고 쓰지 않는다.

## 2. 원칙

| # | 원칙 | 어기면 |
|---|---|---|
| P1 | firmware-rak(커밋 2b18b17)과 **뜻·글자·바이트가 같게** 옮긴다. 다르게 한 곳은 PORTING.md 에 이유와 함께 적는다 | 앱·파서·워치가 조용히 어긋난다 |
| P2 | **통과는 보드에서 잰 값으로만** 적는다. 빌드 통과·코드 읽기·맥 흉내는 "빌드 ✅" 칸까지만 | "돌아간다" 를 "맞다" 로 착각한다 |
| P3 | 합격 기준은 **firmware-rak 을 같은 자리·같은 조건에서 잰 값과 대조**하거나, boat-device-checklist 의 판정 문장을 그대로 쓴다 | 기준을 내가 지어낸다 |
| P4 | **사람 손(다시 꽂기·단추·다른 기기)이 드는 시험은 한 번에 판정되는지 먼저 따지고** 부탁한다. 무엇이 확인되고 무엇이 안 되는지 미리 적는다 | 09-15 다시 꽂기를 네 번 시켰고 증명은 못 했다 |
| P5 | 한 번에 한 단계만 보드에 올린다. 새 판을 올리기 전에 앞 단계 시험이 끝났는지 이 표로 본다 | 무엇 때문에 깨졌는지 못 가른다 |
| P6 | NVS 는 지우지 않는다. SD 는 포맷하지 않는다. 사용자 맥 WiFi 는 안 바꾼다 | 설정·기록을 잃는다 |
| P7 | 커밋마다 WiFi 이름·비밀번호 검사 0건 (`/usr/bin/grep`). 푸시는 사용자가 말할 때만 | 비밀이 샌다 |
| P8 | 칸을 채울 때마다 이 파일을 고치고 커밋한다. 새 세션은 이 파일부터 연다 | 세션이 끊기면 어디까지 했는지 모른다 |

## 3. "이사 끝" 판정

아래가 **모두** ✅ 일 때만 "firmware-idf 로 이사 끝" 이라고 쓴다.
- 4장 표의 모든 줄이 보드 시험 ✅ (하드웨어가 없어 못 하는 줄은 사용자가 "빼도 된다" 고 한 것만 제외)
- 5장 속도 비교에서 firmware-idf 가 firmware-rak 보다 빠르다는 실측 (같은 자리·같은 파일·같은 기기)
- 6장 boat-device-checklist 05·07·10·11·12 를 firmware-idf 로 다시 돌려 통과 (체크리스트 "기록·통신 변경" 때 다시 할 항목)

## 4. 기능 표

상태 표시: ⬜ 안 함 · 🔶 일부 · ✅ 통과 · ❌ 실패. **보드 시험 칸이 ✅ 가 아니면 그 기능은 안 된 것이다.**
보드에 지금 올라가 있는 판: **저장소 전체 판 1~7단계 + USB 고침** (커밋 0138fec 이후 app_main, `-B ~/esp/build-sail`, 0x181830) — 09-15 19:17 올림.

**전체 판 5분 점검 (09-15 19:17, 포트 한 번, 사용자 "새 전체 판 + 5분 점검" 고름)**
- 켜짐 1번 · Guru 0 · abort/스택 0. 켤 때 줄: [USB] int_ena 0x4 · [BOOT] · [WDT] 30초 · [PWR] GPIO14 · [GPS] UART1 · [BTN] 저장 버튼 GPIO2 · [IMU] 붙음 0.99 g · [OLED] 붙음 · [LORA] 922.55 SF7 BW500 8 dBm · 전파시간 14 ms · [BLE] advertising SAIL-random() 0/3 · 남은 메모리 146231
- 1 Hz 상태 줄 나옴 (SOG `--.--` · 모드 b · 전압 4.14V · seq 1초마다 +1 · ADVERTISING)
- `rec on` 16초 → 세션 106: NAV 10.16 Hz · IMU 100.00 Hz 등간격 1680/1680 · CRC 0 · 버린 줄 0 · 정상 닫힘 · `rec check` 깨끗
- ★ 기록 시작 **전** `rec` 에 IMU FIFO "넘칠 뻔 1번" (기록 중엔 0). 켤 때 BLE·화면·LoRa 올리는 동안으로 보임 [추측] — G06 에서 본다

## 7.5 09-15 밖 시험 — 사용자가 들고 나감 (전체 판)

사람 손·밖이라야 되는 줄만 몰았다 (P4). 노트북 없이 된다. 돌아오면 USB 로 파일을 받아 판정한다.

| 순서 | 체크리스트 ID | 사용자가 할 일 | 돌아와서 판정할 것 |
|---|---|---|---|
| 1 | E01 | 하늘이 열린 곳에서 켜고 1~2분 기다린 뒤 **단추 2초** → 화면에 REC | 단추로 기록이 시작됐나 · 화면 REC |
| 2 | G02 · K06 | 걷거나 멈추기를 섞어 **10분 이상** 기록 (정지 1분 · 걷기 몇 분) | fix 잡힘 · 속도·침로 · itow 100 ms · NAV 10 Hz |
| 3 | G06 · S03 | (2 와 같은 기록) 화면 켠 채 | IMU 100 Hz 등간격 · FIFO 넘침 0 · 버린 줄 0 |
| 4 | E01 | 중간에 **단추 짧게** 1~2번 (마킹) | 마킹 표식이 HLG 에 있나 |
| 5 | S01 | 기록 중 화면 **사진** 1장, 멈춘 뒤 1장 | firmware-rak 화면과 같나 |
| 6 | B02 | (가능하면) 폰 앱을 붙여 속도·방위가 뜨는지 | 앱에 값 |
| 7 | E01 | **단추 2초** 로 기록 종료 → 화면 SAVING 뒤 사라짐 | 정상 닫힘 · `rec check` 깨끗 |

- 단추 5초(끄기)는 이번에 **하지 않는다** — 깊은잠·깨기(E02)는 아직 보드에서 한 번도 안 돌려 봤다. 끄려면 USB/배터리를 뺀다
- 알 수 없는 동작(화면 멈춤·재부팅·REC FAIL)이 보이면 **시각을 적고 사진** — 돌아와 켤 때 [BOOT] 이유와 코어덤프를 먼저 본다
