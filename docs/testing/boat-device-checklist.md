# 보트 장치 테스트 체크리스트 — 시험 방법 포함

작성: 2026-09-15. 시험 결과는 아직 모두 **미실시**다. 아래 숫자는 초기 개발 목표이며, 검증된 제품 성능이나 인증 기준이 아니다.

**먼저 할 것:** ① 나침반 비교 → ② 기울기 → ③ 화면·기록 대조 → ④ 정지·저속 → ⑤ 기록 시작·종료. 이 다섯 가지를 확인한 다음 실제 항해에서 반복한다.

각 항목의 체크박스는 시험을 실시했을 때 체크한다. 판정은 별도로 `통과 / 실패 / 미측정`으로 적는다. 기준 장비나 로그가 부족해서 판단할 수 없으면 통과로 처리하지 않는다.

## 준비물과 공통 기록

- [ ] 독립된 나침반, 수평계 또는 각도계, 비자성 받침대, 방향 표시용 테이프 준비.
- [ ] 줄자, 초시계, 촬영용 폰, 실제 사용할 워치 준비. 촬영용 폰도 센서와 나침반의 값에 영향을 주지 않는 거리에 둔다.
- [ ] 고장 시험에는 실제 항해 기록이 없는 여분의 SD와 시험용 장치를 사용한다.
- [ ] 케이스에 ‘뱃머리 방향’ 화살표를 붙이고, 장착 위치와 방향을 사진으로 남긴다.
- [ ] 아래 정보를 적는다. 시험 중 보정이나 설정을 바꾸면 새 시험으로 구분한다.

| 항목 | 기록 |
|---|---|
| 날짜·장소·시험자 / 장치 ID | |
| 펌웨어·앱 버전 / SD / 시작 배터리 | |
| 보트·장착 사진 / 자북 또는 진북 | |
| 센서 축·장착 오프셋·편각·자력 보정 설정 | |
| 기준 나침반·각도계 / 영상 / 세션 번호 | |

영상 시작 때 장치 시각과 세션 번호를 찍는다. 조작할 때 “기록 시작”, “회전 시작”, “블루투스 끔”을 말해 두면 나중에 로그와 맞추기 쉽다.

## 육상에서 먼저

### 01. 설치 위치에 자기 간섭이 없는가? · 약 10분

- [ ] 시험 실시
1. 나침반을 수평으로 놓고, 방향을 유지한 채 장착 예정 위치 안팎으로 옮겨 값을 비교한다. 차량·철제 테이블·철근 바닥처럼 주변 자체가 영향을 주는지도 확인한다.
2. 실제 케이스·브래킷·나사·배터리를 포함한 장치로 반복한다. 거리를 늘려도 나침반 값이 더 변하지 않는 곳을 비교 기준 위치로 잡는다.
3. 장치 기록, BLE·Wi-Fi·LoRa, 충전 등 지원되는 상태를 하나씩 바꾼다. 보트의 평소 전기장치도 켜고 끈다. 각 상태에서 10초씩 관찰한다.
4. 간섭이 있으면 위치나 부품 배치를 바꾸고 처음부터 반복한다. 강한 자석을 일부러 가까이 대는 시험은 하지 않는다.

**판정:** 같은 방향인데 위치나 전기 상태에 따라 반복적으로 헤딩이 달라지면 원인 해결 전 보류. 초기 목표는 상태 변화에 따른 추가 오차 3° 이하이며, 기준 나침반으로 그 차이를 구별할 수 있어야 한다.

### 02. 나침반과 8방위에서 맞는가? · 약 20분

- [ ] 시험 실시
1. 장치와 나침반이 같은 북쪽 기준을 쓰게 한다. 자북과 진북을 섞지 않는다. 자북을 진북으로 바꿀 때는 장소·날짜에 맞는 편각을 적용한다.
2. 장치의 뱃머리 화살표와 기준 나침반의 진행 방향선을 평행하게 맞춘다. 서로 떨어뜨려 놓되 같은 방향을 보게 한다.
3. 아래 8방위 부근에서 각각 멈추고 10초간 촬영한다. 정확히 45°를 만들 필요는 없고, **실제 나침반 읽음값**을 기록한다.
4. 시계 방향과 반시계 방향으로 한 바퀴씩 반복한다. 이상이 있으면 해당 방위를 다시 측정한다. 최종 검증에서는 각 방향을 3회 반복한다.
5. 한 방향에서 보정했다면 그때 사용하지 않은 방향에서도 검증한다. COG에 맞추려고 오프셋을 바꾸지 않는다.

### 03. 배가 기울어도 HDG가 유지되는가? · 약 20분

- [ ] 시험 실시
1. 받침대의 앞뒤 방향을 고정하고 평면 HDG를 10초간 기록한다. 나침반은 별도로 수평을 유지한다.
2. 앞뒤 방향을 바꾸지 않고 좌우 기울기만 `0 → +10 → +20 → +30 → 0 → −10 → −20 → −30 → 0°`로 바꾼다. 각 자세를 10초 유지한다.
3. 동·남·서·북 방향에서 반복한다. 이후 앞뒤 기울기만 바꾸고, 마지막에 좌우·앞뒤 기울기를 함께 준다.
4. 힐·피치 표시도 각도계와 비교한다. 좌현·우현으로 기울였을 때 부호가 일관적인지 확인한다.
5. 육상에서 수직·뒤집힌 자세를 거쳐 원위치로 되돌린다. 이때 실제 배를 전복시킬 필요는 없다.

**판정:** 초기 목표는 기울기에 따른 추가 헤딩 오차의 95%가 3° 이하. 특정 기울기에서 90°·180°가 바뀌거나 원위치 복귀 후 다른 값이 남으면 실패. 계산이 불가능한 자세에서는 그 상태를 드러내야 한다. 힐·피치 각도 오차도 별도로 기록한다.

### 04. 회전 반응과 재부팅·재장착이 일관적인가? · 약 15분

- [ ] 시험 실시
1. 각도 표식과 화면을 함께 촬영하며 장치를 45°와 90°씩 양쪽으로 회전시킨다. 각 3회 반복한다.
2. 실제 회전 시작부터 숫자의 첫 변화까지, 회전 종료부터 새 방향에 안정될 때까지 시간을 잰다. 북쪽을 통과하는 회전도 포함한다.
3. 같은 표시 위치에서 전원을 껐다 켜기 3회, 탈착·재장착 3회를 실시한다. 보정·장착 설정도 확인한다.

**판정:** 회전 방향이 반대로 나오거나 북쪽 통과 때 한 바퀴 튀면 실패. 초기 응답 목표는 1~3초 안에 변화를 읽을 수 있는 것. 재부팅·재장착 후 추가 오차 목표는 3° 이하이며 설정이 보존되어야 한다.

결과: ______ / 첫 반응: ____초 / 안정까지: ____초 / 재장착 최대 변화: ____°

### 05. OLED·워치·저장 후 앱이 같은 측정을 보여 주는가? · 약 15분

- [ ] 시험 실시
1. 기록을 켜고 장치를 서로 다른 세 방향으로 향하게 한다. 각 방향은 30초 유지하고, 중간에 기울기도 한 번 바꾼다.
2. OLED와 워치를 함께 촬영한다. 종료 후 같은 세션의 HLG와 TXT가 있으면 함께 확보한다.
3. 앱에서 같은 시각을 찾아 HDG·COG·속도·힐을 대조한다. 북쪽 기준, 단위, 보정, 갱신 주기 차이를 먼저 확인한다.
4. 세션 46에서 확인한 형식처럼 HLG에 원시 센서값만 있고 HDG가 직접 저장되지 않았다면, 앱의 값은 재계산 결과로 구분한다. 당시 설정이 없어 재현할 수 없으면 그 사실을 기록한다.

**판정:** 안정 구간의 값은 같은 정의·설정을 적용했을 때 반올림과 갱신 차이로 설명되어야 한다. 앱에서만 일정 각도 돌아가거나 기울일 때만 크게 달라지면 실패. HDG를 COG와 같게 만드는 것이 목표가 아니다.

### 06. 정지와 아주 느린 이동을 구별하는가? · 약 45~60분

- [ ] 시험 실시
1. **정지:** 하늘이 열린 육상에서 장치를 완전히 고정하고, 수신이 안정된 뒤 10분 기록한다. 속도의 중앙값·최댓값, 0.2 kn 초과 시간 비율, `--` 비율을 남긴다. 다른 날에도 반복한다.
2. **저속:** 평탄한 곳에 10m 구간과 중간 눈금을 표시한다. 가능하면 비자성 받침이나 수레로 장치를 같은 방향·높이로 이동시킨다. 구간 앞에서 출발해 일정한 속도로 들어가고 뒤까지 계속 이동한다.
3. 아래 시간을 참고해 0.3·0.5·0.8 kn 부근을 각각 3회 이동한다. 실제 측정 시간으로 평균 속도를 계산하고, 같은 구간 장치 평균과 비교한다. 충분히 느리게 이동할 수 있으면 0.2 kn도 추가한다.
4. **반응:** 별도 시험에서 `정지 20초 → 이동 20초 → 정지 20초`를 3회 반복한다. 눈금·장치 움직임·화면을 영상에 함께 담아 출발과 정지 후 지연을 잰다.

| 참고 속도 | 10m를 이동하는 시간 | 실제 시간 | 실제 평균 속도 | 장치 평균 | 0 표시 / 무효 표시 비율 |
|---|---|---|---|---|---|
| 0.2 kn | 약 97.2초 | | | | |
| 0.3 kn | 약 64.8초 | | | | |
| 0.5 kn | 약 38.9초 | | | | |
| 0.8 kn | 약 24.3초 | | | | |
| 1.0 kn | 약 19.4초 | | | | |

계산: `평균 속도(kn) = 실제 거리(m) ÷ 실제 시간(s) × 1.94384`. 위 시간은 속도를 맞추는 참고값이며, 실제 이동 속도는 반드시 실측한다.

**판정:** 출발·감속을 약 1~3초 내 반영하는지 확인한다. 실제 0.3 kn 이동을 오래 0으로 유지하거나, 정지에서 반복적으로 큰 속도가 나오면 문제다. `--`만 늘려 숫자를 조용하게 만든 경우도 사용 가능 비율로 드러내야 한다. 정지 표시 정책과 저속 허용 오차는 이 결과를 보고 확정하며, 확정 전에는 속도 전체를 ‘통과’로 쓰지 않는다.

10m 평균은 평균 속도 검증용이다. 그 값만으로 1~3초 반응을 입증할 수 없고, 반응 시험 영상의 실제 이동 변화를 따로 봐야 한다. 다른 폰 GPS도 이 저속 구간의 정답으로 삼지 않는다. 부두에 묶인 보트는 실제로 움직일 수 있으므로 육상 정지와 별도 시험으로 취급한다.

### 07. 기록을 반복해도 빠지거나 다시 켜지지 않는가? · 약 30분

- [ ] 시험 실시
1. 번호를 적으며 `기록 시작 → 30초 유지 → 기록 종료 → 10초 관찰`을 10회 반복한다.
2. 다음 10회는 앱을 연결한 상태에서, 마지막 10회는 평소 사용법대로 종료 후 전원을 껐다 켜며 반복한다.
3. 각 파일의 번호·시작·끝·길이를 실제 조작과 비교하고 모든 파일을 끝까지 검사한다.
4. 종료 도중 화면과 버튼이 반응하는지, IMU 기록에 공백이 생겼는지, 종료 후 저절로 새 기록이 시작했는지 확인한다.

**판정:** 30회 모두 의도한 세션이 존재하고, 과거 파일 덮어쓰기·손상·의도하지 않은 재시작이 0건. 파일이 목록에 보이는 것만으로 통과하지 않는다.

### 09. 항해 중 · 평소 항해에 관찰 구간을 넣기

- [ ] 직진 1분 구간을 양쪽 택에서 각각 3회 확보한다. 가능한 조건에서 리치·풍하 구간도 남긴다.
- [ ] 택·자이브를 할 때 시각을 메모하거나 말로 녹음한다. 풍향은 계기 또는 관찰 출처와 함께 적고, 나중의 데이터 추정과 구분한다.
- [ ] 약풍의 느린 구간 2~3분을 확보한다. 실제 전진·흔들림·정지를 영상이나 독립된 기준과 함께 남긴다.

### 12. 카드 오류·느린 종료·전원 차단에서 무엇을 잃는가?

- [ ] 닫기를 20초 지연: 기록 종료 후 센서·화면·버튼이 살아 있는지, 늦게 끝난 파일도 정상 마무리되는지 확인.
- [ ] 쓰기 실패와 수동 정지를 거의 동시에 발생: 정지 후 30초 이상 관찰해 자동 재시작 여부 확인.

- [ ] GPS 입력 중단·복귀 또는 지원되는 GPS 전원 재시작: 오래된 값이 무효 처리되고, 복귀 후 속도 출력과 설정이 회복되는지 확인.

### 16. 함대 LoRa가 끊김·중복·재연결을 숨기지 않는가?

- [ ] 수신 전용 0번 1대와 서로 다른 번호의 송신 보드 2대를 같은 펌웨어로 맞춘다. 각 보드의 버전·배 번호·채널을 먼저 기록한다.
- [ ] 실내 PPS 전 상태로 2분 유지한다. 두 송신 보드가 5~8초 확인 신호로 보이고 위치·SOG·COG는 `—`인지 확인한다.
- [ ] 실외에서 PPS를 잡고 10분 유지한다. 두 배가 약 1 Hz로 갱신되고 위치·SOG·COG·REC·배터리가 각 송신 보드와 맞는지 촬영한다.
- [ ] 두 송신 보드를 같은 배 번호로 바꿔 30초 운용한다. 앱이 `번호 충돌`을 표시하고 그 번호를 지도·A/B 비교에서 제외하는지 확인한 뒤 번호를 되돌린다.
- [ ] 송신 보드 한 대를 끈다. 직접 수신이 끊긴 뒤 다른 배의 `heard`에는 남는 상태와, 어느 배도 못 듣는 상태가 구분되는지 확인한다. 마지막 위치 마커는 20초 뒤 사라져야 한다.
- [ ] 함대 화면→항해 리뷰→함대 화면을 3회 반복하고 앱을 강제 종료해 다시 연다. 화면 전환만으로 수신 보드 LoRa가 꺼지지 않고, 저장한 0번 보드에 다시 연결되는지 확인한다.
- [ ] 10분 끝에 앱의 BLE 전달 누락, 배별 프레임 누락, 보드 수신 링 버림, 앱 전달 큐 버림, BLE 알림 실패 수를 기록한다. 하나라도 0이 아니면 발생 시각·배 수·RSSI/SNR을 남긴다.
- [ ] 2대부터 시작해 실제 목표 척수까지 단계적으로 늘린다. 각 단계에서 예상 패킷 수, 실제 수신 수, 가장 긴 공백, 거리별 RSSI/SNR을 남긴다.

**판정:** 잘못된 배의 위치를 정상처럼 그리거나, 같은 번호를 조용히 덮어쓰거나, PPS가 만료됐는데 같은 GPS 초라고 비교하면 실패. 주말 시연의 최소 기준은 2대 10분 동안 보드·앱 버림 0, 번호 혼동 0, 재연결 3/3 성공이다. 최대 척수와 거리는 실측 전에는 통과로 쓰지 않는다.
