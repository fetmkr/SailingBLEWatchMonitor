# 방위 — 기울기 보정

## 2026-09-16 IDF 헤딩 구현 — 식 5 (보드 적용·실외 검증 전)

사용자 요청으로 MPU-9250/AK8963의 HDG를 **자이로 적분 + 가속·자력 피드백** 하나로 바꿨다.
가속도 순간값을 매번 중력으로 간주하던 식 3은 비교 진단으로 남긴다. OLED·BLE·TXT·HLG는
`boatHeadingDeg()` → `heading::Filter` 결과를 읽는다. 기존 힐·피치 표시 계산은 이번 범위에 포함하지 않았다.

- 근거: [Olson/Honeywell 1994](https://transducer-research-foundation.org/technical_digests/HiltonHead_1994/hh1994_0197.pdf)는 자이로 없이 자력·중력 투영을 쓴다.
  [PNI TCM2, 2004](https://www2.etown.edu/wunderbot/DOWNLOAD/TCM2-50/Manual_TCM2-50.pdf)는 기울기 센서와 IIR 댐핑을 설명하며 운동 가속의 한계도 명시한다.
  그러므로 자이로가 모든 전자나침반의 필수 조건이라는 주장은 하지 않는다.
- 선택: 우리 센서에는 자이로가 있고, 실제 회전 반응을 유지해야 하므로
  [x-io Fusion v1.3.3](https://github.com/xioTechnologies/Fusion/tree/v1.3.3)의 작은 상보 필터를 사용한다.
  원본 MIT 파일은 `firmware-idf/components/fusion`, 어댑터는 `main/heading_filter.{h,cpp}`.
  복잡한 항법 EKF, COG 보정, 추가 출력 평활은 넣지 않았다.
- 고정 설정: NED / 100 Hz / gain 0.5 / gyro ±1000°/s / 가속·자력 거절 10° / 복구 5초.
  시작은 현재 자력·가속 자세로 초기화하고 원본의 3초 수렴 구간에는 `?`.
  거절이 지속되면 원본의 복구 절차가 다시 입력을 받아들이므로 지속적인 자기 왜곡을 해결하는 알고리즘은 아니다.
- 최종 HDG에는 PNI TCM2 방식의 원형 1차 IIR을 한 번 적용한다(반감기 1초). OLED·BLE·TXT·HLG 모두 같은 값이다.
  359°↔0°는 최단 각도 차이로 계산한다. 원본 Fusion 값은 화면 대체값으로 쓰지 않는다.
- MPU→AK 축 정렬 후 기존 장착 축으로 앞·오른쪽·아래 변환. 오프셋·편각은 출력에 한 번만 더한다.
  기존 장착 +155.7°·편각·자력 보정값은 임의 변경하지 않는다.
- FIFO 표본마다 갱신하며 반복 시각은 무시한다. 시각 간격이 5~20ms 밖이면 재초기화하여 공백을 적분하지 않는다.
  재연결·자이로/자력 보정·축 변경도 상태를 초기화한다. REC 시작만으로 무조건 재초기화하지 않는다.
- 자력계는 실제 8 Hz(읽기 10 Hz). 최신 값을 최대 250ms 유지하여 피드백에 사용한다.
  이는 100개의 독립 자력 관측이 아니다. 자력이 늦으면 최대 2초까지 자이로 추정값과 `?`,
  그 이후 또는 IMU 수신이 250ms 넘게 없으면 `---`. 초기화·자력 거절/복구 중에도 유효 추정값은 숨기지 않는다.
  걷기·파도 때문에 가속도 피드백만 거절된 것은 정상 동작이므로 `?`를 붙이지 않고 진단값에만 남긴다.
- HLG 식 ID 5, NAV event bit 3(0x08)은 표시 HDG 품질 주의. NAV 크기·원본 IMU/자력·기존 식 1~4는 유지.
  기록 시작 이전 필터 상태와 정확한 자력 획득 시각이 없어 단일 NAV로 같은 값을 재계산할 수 없다.
  앱은 저장 HDG를 쓰고 식 5의 재계산 단추를 제공하지 않는다.

검증: `tools/verify.sh quick`에 실물과 같은 C 소스/어댑터 시험을 포함했다.
24축 배정 × 8방향 × 3기울기 = 576자세, 45°/s 기울인 회전·북쪽 통과(최대 오차 1.955°),
고정 방향에 2/3 Hz 이동 가속을 더한 시험(최대 오차 0.223°, 순간 기울기 식 45.283°),
짧은 자기 교란·센서 공백·재연결·중복 시각·NaN·시계 순환을 검증했다. 이는 합성 입력의 결과다.

실제 세션 118 전체를 C++ 구현으로 순서대로 재생했다. GPS만으로 고른 직진 10초 구간 17개의
HDG 중앙 90% 범위의 중앙값은 기존 43.47° → 새 구현 20.85°.
같은 기록의 단순 가속/방위 IIR(시정수 1초)은 18.08°로 더 매끄러웠지만, 실제 회전도 지연시킨다.
**재생의 매끄러움은 절대 정확도 증거가 아니다.** 손의 실제 방향·기록 이전 상태·센서 획득 시각은 미상이다.
자료: `walk-heading-20260915/implemented-heading-summary.json` (사용자 작업 폴더).

남은 검증: `boat-device-checklist.md` 02~06의 물리 시험. Iris 50과 자북 기준을 맞춘 8방향,
같은 방향에서 기울이기/걷기, 90° 회전 반응, 실제 OLED·BLE·SD 대조, REC 10분간 FIFO 손실 확인.
일정한 20여 도 차이는 장착 기준·자북/진북·자력 보정/배선 환경을 따로 측정해야 하며, 이번 변경으로 해결됐다고 하지 않는다.

- 앱의 “배를 수평으로 한 바퀴” 안내는 현재 3차원 보정의 분포 검사와 맞지 않았다.
  장치 자체를 여러 자세로 기울이고 뒤집어 수집하도록 고쳤다. 설치 후 환경 보정의 제품 절차는 별도 검증이 필요하다.
- 보정 결과를 1 Hz 진행과 따로 표시하고, 워치·아이폰에서 가득 찬 점을 다시 모을 수 있게 했다.
  128/128을 보정 성공으로 표시하지 않는다. 보정 식·수락 문턱·NVS 저장 방식은 변경하지 않았다.
- 기록 중 설정 잠금은 유지하며, 그 거절도 시리얼뿐 아니라 BLE 응답으로 전달한다.
- 검증: Swift 결과 유지·재시도 시험, 실제 보드 명령 함수의 호스트 시험, 기존 펌웨어 로직 시험,
  iOS·watchOS 시뮬레이터 및 ESP-IDF 빌드. 물리 기기의 새 수집·저장·재부팅 유지 확인은 아직 안 했다.

## 1. 얼마나 틀리나

한국 자기장은 아래로 53° 로 꽂힌다. 배가 누우면 그 아래 성분이 옆 축으로
새어 들어와 방위를 밀어 버린다.

계산해 본 값이다. 뱃머리 방향을 5° 씩 다 돌려본 최대 오차.

    힐 10°  →  13.6° 틀림
    힐 20°  →  29.1° 틀림
    힐 30°  →  50.4° 틀림

**딩기는 20~30° 로 눕는다.** 그리고 우리가 재려는 leeway(뱃머리와 실제 가는
방향의 차이)는 보통 **3~8°** 다.

    오차 29°  vs  재려는 값 5°

**오차가 재려는 값보다 네 배에서 열 배 크다.** 그대로면 leeway 는 숫자가
아니라 잡음이다.

## 2. 고친 방법

식은 [INSLIB](https://github.com/jnz/inslib) 의 `ahrs_mag_detilt` 를 그대로
옮겼다 (MIT). 자력 벡터를 힐·피치만큼 되돌려 수평으로 눕힌 뒤 atan2 한다.

    ty = cos(힐)·오른쪽 − sin(힐)·아래
    tz = sin(힐)·오른쪽 + cos(힐)·아래
    hx = cos(피치)·앞    + sin(피치)·tz
    방위 = atan2(−ty, hx)

### ★ 힐·피치 설정을 안 쓴다

`gHeelAxis` / `gPitchAxis` 를 넣고 싶었지만 그러면 안 된다.
**보드를 세워 달아서** 평형일 때 raw 피치가 86° 로 나온다. 그 값을 넣으면
보정이 엉뚱해진다.

대신 **가속도계로 중력 방향을 직접 잰다.** 그러면 보드를 어떻게 달았든 상관없다.

    가속도계 → 자력계 좌표로 옮김 → 앞·오른쪽·아래로 뽑음 → 힐·피치 계산

### ★ 두 센서의 축이 다르다

한 칩인데 자력계만 따로 든 칩(AK8963)이라 축이 다르고 라이브러리가 안 맞춰 준다.

    자력 X = 가속 Y      자력 Y = 가속 X      자력 Z = −가속 Z

바꾸는 식이 제 짝이라 그대로 뒤집어 쓰면 된다 (`accInMagFrame`).

### 앞·오른쪽·아래를 어떻게 아나

지금 설정이 이미 두 축을 알려준다. 방위를 `atan2(a, b)` 로 구하는데
자기 방위의 정의가 `atan2(−오른쪽, 앞)` 이므로

    앞     = magAxis(gHdgAxisB) · gHdgSignB
    오른쪽 = magAxis(gHdgAxisA) · (−gHdgSignA)
    아래   = 남은 축, 부호는 오른손 법칙 (아래 = 앞 × 오른쪽)

**아래 축 부호만 확인이 필요하다.** 그래서 `hdgtilt` 를 만들었다.

## 5. 책상에서 손으로 해본 결과 (2026-09-09)

세 번 돌렸다. 판마다 조건이 달라서 나란히 놓고 봐야 한다.

    기울인 폭   평평     보정     자이로 뺀 나머지   자력 크기
    110°       83.9°   27.2°    —                 —
     90°       52.7°   32.7°    —                 33.9~47.6 µT (16%)
     40°       14.7°   27.5°    13.3°             48.9~58.3 µT (16%)

**크게 기울인 두 판에서는 보정한 쪽이 확실히 덜 흔들렸다.** 84 → 27, 53 → 33.

### 여기서 배운 것 셋

**하나. 아래 축 부호가 맞다.** 두 갈래로 확인했다.

    오른손 법칙으로 뽑은 값       +X
    가속도계가 가리키는 아래 방향  +X

**둘. 손으로 기울이면 같이 돈다.** 3차에서 알짜 회전은 +6.5° 인데 합계가 35.3° 였다.
왔다갔다 돌았다는 뜻이고, 그동안은 방위가 **진짜로** 바뀐 것이라 오차가 아니다.
그래서 자이로가 말하는 회전을 빼고 보게 만들었다. 빼고 나면 13.3° 가 남는다.

**셋. ★ 책상은 자기적으로 더럽다.** 판마다 자력 크기 자체가 달랐다.

    1차  29 ~ 42 µT      2차  34 ~ 48 µT      3차  49 ~ 58 µT

한국의 지구 자기장은 약 50 µT 로 **한자리에서 일정하다.** 판마다 다르다는 것은
맥·케이블·책상 철제가 자기장을 휘고 있다는 뜻이다.

**책상에서 하는 확인은 여기가 한계다.**

### 명령이 잘못 판정했던 것

3차에서 기울기가 40° 밖에 안 됐는데 "아래 축 부호가 뒤집혔다" 고 단정했다.
기울기가 작으면 두 값이 원래 비슷한데 그걸 오차로 본 것이다.
지금은 **40° 넘게 기울이지 않으면 아예 판정하지 않는다.**

## 6. 하드아이언 보정 — 했다 (2026-09-10)

### 왜 필요했나

자력계는 지구 자기장만 재지 않는다. **보드에 붙은 쇠붙이가 만드는 자기장까지
같이 잰다.** 그건 보드와 같이 도니까 보드 입장에서는 늘 같은 방향의 상수다.

    잰 값 = 지구 자기장(방향만 도는 일정한 크기) + 상수

그래서 돌리기만 해도 크기가 변했다. 한 판 안에서 16~45% 흔들렸다.

### 어떻게 찾나

상수가 없으면 잰 값들이 **원점을 중심으로 한 공 껍질** 위에 놓인다.
상수가 있으면 공이 통째로 밀린다. **밀린 중심이 그 상수다.**

    x²+y²+z² = 2ax + 2by + 2cz + d   를 최소제곱으로 푼다
    중심 (a,b,c) = 치우침,  반지름 = sqrt(d + a²+b²+c²)

선형이라 반복이 없다. 못 도는 경우가 없어서 실시간에 안전하다.

**자세도 COG 도 안 쓴다. 기하학만 쓴다.** 그래서 순서상 3번이고 4번(박스가
돌아앉은 각)보다 먼저 와야 한다. 안 그러면 남은 치우침이 뱃머리 방향마다 다른
오차를 만들고 그게 leeway 인 척 섞인다.

### 점 고르는 법

다 저장할 수 없으니 **서로 6 µT 이상 떨어진 것만** 128개까지 담는다.
이 한 규칙이 두 가지를 해준다.

  · 가만히 있으면 안 쌓인다 (같은 자리라 걸러진다)
  · 골고루 돌려야 채워진다 (한쪽만 보면 금방 멈춘다)

플래시 전에 컴퓨터에서 검산했다. 아는 치우침을 넣고 되찾는지 봤다.

    사방 100% 덮음, 잡음 0.5    오차 0.1 µT
    사방  25% 덮음, 잡음 1.0    오차 0.5 µT
    사방  12% 덮음, 잡음 1.0    오차 3.7 µT   ← 여기서 무너진다

그래서 축별 퍼짐을 보여준다. 좁은 축이 덜 돌린 쪽이다.

### 실기기 결과

    magcal on   → 사방으로 돌림 → 128/128 점, 퍼짐 96/91/94 µT
    magcal stop → 치우침 4.0 15.3 -2.4 µT
                  크기 30~62 µT  →  47.5 ± 2.16 µT

**★ 맞춰 나온 반지름이 47.5 µT 다.** 한국 지구 자기장이 약 50 µT 다.
이건 코드가 맞는지와 **상관없는 확인**이다. 엉뚱하게 맞췄으면 이 숫자가 안 맞는다.

### 전후 비교

    |                 자력 크기 흔들림   기울기 보정 효과
    | 보정 전          16 ~ 45%         84° → 27°  (3.1배)
    | 보정 후           5 ~  8%         86° → 15°  (5.7배)

**치우침을 빼니 기울기 보정도 같이 좋아졌다.** 식은 원래 정확했고 입력이
틀렸던 것이라 예상한 대로다.

### 쓰는 법

시리얼과 BLE 양쪽에서 같은 말을 쓴다 (PROTOCOL.md §9).

    magcal        지금 상태
    magcal on     모으기 시작 (1초마다 점 수와 축별 퍼짐을 알려준다)
    magcal stop   맞추고 NVS 에 저장
    magcal clear  지운다

★ **버튼으로 안 만들었다.** 화면이 필요한 작업이다 — 몇 점 모았나, 어디가
비었나, 끝나고 좋아졌나를 봐야 한다. 그리고 버튼은 이미 셋이 차 있다.

★ **깨끗한 데서 해야 한다.** 맥·철제 책상은 보드와 같이 안 돌기 때문에
그런 데서 재면 그것까지 상수로 빼버린다. 나무 위, 전자기기에서 한 팔 떨어져서.

★ **보드에 붙을 것을 다 붙인 채로.** 배터리·케이스·안테나가 원인이다.

## 7. 자이로를 100 Hz 로 적분한다

`hdgtilt` 에서 "손으로 기울이다 같이 돈 각" 을 재는데, 처음에는 **진단 명령
안에서 4 Hz 로 적분했다.** 출력을 읽기 좋게 하려고 넣은 `delay(250)` 자리에서
같이 재버린 것이다.

값이 통째로 틀렸다. 자이로로 회전을 빼면 흔들림이 **줄어야 하는데 늘었다**
(21.0° → 30.8°). 손으로 흔들면 각속도가 4 Hz 보다 훨씬 빨리 변해서 사이를
다 놓친다.

**재는 자리는 값이 오는 자리여야 한다.** `imuDrainFifo` 가 100 Hz 벌을 하나씩
꺼내는 그 자리로 옮겼다. 같은 동작을 4 Hz 는 37.8°, 100 Hz 는 -4.4° 라고 한다.
기울이기만 했으니 뒤가 맞다.

그리고 각속도를 **몸통 축이 아니라 가속도계가 알려주는 진짜 수직**에 투영한다.
배가 기울면 몸통 축은 이미 수직이 아니다.

## 8. 다음

기울기 보정 식은 정확하다 — 검산에서 72가지 전부 0.5° 미만이었다.
**남은 오차는 입력이 틀려서 나온다.**

한 판 안에서도 자력 크기가 16~45% 흔들린다. 돌리기만 했는데 크기가 변한다는 것은
보드 위의 쇠붙이가 만드는 **고정 편차(하드아이언)** 가 얹혀 있다는 뜻이다.

그래서 순서가 이렇게 된다.

    1. 하드아이언 보정        ← 다음
    2. 자기 편각 (한국 약 8° 서편)
    3. 자이로 필터 (INSLIB 의 ahrs_t, 656 바이트)

자이로 필터를 먼저 넣어봐야 틀린 입력을 매끄럽게 만들 뿐이다.

## 7. 아직 안 한 것

**바꾸지 않았다.** 화면·BLE·기록에 가는 값은 여전히 평평한 쪽이다.
물 위에서 둘을 대조한 뒤에 정한다. 속도의 도플러 대 위치차분과 같은 방식이다.

그리고 아직 빠진 것 둘.

  · **자기 편각** — 자북과 진북의 차이. 한국은 약 8° 서편이다.
    INSLIB 에 WMM 이 들어 있어 위경도만 주면 나온다.
  · **자이로** — 지금은 가속도계만 본다. 파도나 돌풍 중에는 가속도계가
    중력 말고 다른 것도 재서 힐이 틀린다. 그때가 정확히 알고 싶은 순간이다.
    INSLIB 의 `ahrs_t` 가 656 바이트라 넣을 만하다.

## 9. 2026-09-14 검토 뒤 고친 것

펌웨어 식을 float32 로 그대로 옮기고, 독립적으로 만든 회전행렬(NED, ZYX)로 가상 센서값을
만들어 돌렸다 (scratchpad `heading_check.cpp`).

### 확인된 것

    기울기 보정 식         24가지 축 설정 × yaw·피치 ±30·힐 ±40 → 최대 오차 0.000°
                          아래 축 부호는 24가지 모두 물리 오른손과 같다
    평평한 방위(실제 출력)  힐 10/20/30° → 13.6/29.1/50.4° (§1 과 같다)
    옆가속 0.2 g          보정 방위 15.4° 틀림. |a| 가 정확히 1 g 여도 24.8° 틀리는 경우가 있다
    자력이 125 ms 늦음     힐 60°/s 에서 보정 방위 10.1° 틀림
    hdgtilt 폭            358·359.5·0.5·1·2 를 359° 로 셌다 (원형으로는 4°)
    아래 축 부호만 틀림     기울여도 폭 0, 방위는 40~180° 틀림 → hdgtilt 가 "잘 되고 있다"
    yawRateNow            피치 20°·힐 30°/s → −10.3°/s (실제 방위 변화 0)
    hdg off 1e10 / inf     방위 정규화 while 이 끝나지 않음. NVS 에 남아 켤 때마다 되풀이
    magcal (수평만 돌림)   z 중심 38 µT 틀린 후보가 잔차 0.54 로 저장됨 — 기존 보정을 덮어씀

### 고친 것 (펌웨어)

- **정규화** fmod 로 한 번에 접는다. 유한하지 않으면 무효 (`heading_math.h`)
- **입력** `hdg off` 는 숫자만·-360~360. NVS 에서 읽은 오프셋·축·자력 보정값을 쓰기 전에 검사
- **자기 편각** `hdg decl` 로 장착 오프셋과 따로 둔다. 방위 = atan2 + 오프셋 + 편각. 기본 0
- **자력 표본** I2C 마스터 거울 8바이트(ST2 포함)를 직접 읽어 짧은 읽기·넘침·0 벡터를
  가른다 (`mag_sample.h`). 400 ms 동안 정상 읽기가 없거나, 세 축이 5초 동안 한 번도 안 바뀌면
  (거울이 멈춤) 자력 무효 → 두 방위 함수 모두 무효, BLE magOk 0, HLG mag 0
- **공장 감도값(ASA)** 전원 차단 → Fuse ROM → 읽기 → 전원 차단 → 연속 8 Hz 순서로 직접 읽는다
- **magcal** 후보를 따로 풀고 반지름 25~70 µT · 점 구름의 가장 얇은 방향 두께 ≥ 반지름 10% ·
  잔차 ≤ 10% 를 모두 통과해야 쓴다. 아니면 기존 보정 그대로 (`magcal.h`)
- **보정 방위 입력** 가속 크기가 1 g 에서 0.15 g 넘게 벗어나면 무효 (명백한 경우만 거른다)
- **yawRateNow** ZYX 오일러 방위 변화율 ψ̇ = (q·sinφ + r·cosφ)/cosθ
- **hdgtilt** 원형 폭, 힐은 보정에 쓰는 중력 기준, 부호 판정 문구 없앰. 기록 중에는 막힘
- **hdg ref <참 방위>** 아는 방위에서 두 방위의 오차를 본다
- **재현** TXT 머리에 방위 식·축·오프셋·편각·자력 오프셋을 적고, 기록 중 바뀌면 줄을 남긴다.
  식 5 HLG의 mag는 센서 원본이고, 헤더에 하드·소프트아이언 보정값을 함께 적는다. 옛 식 1~4 파일의 의미는 바꾸지 않는다.

### 안 고친 것

- **보정 방위를 화면·BLE·TXT 로 내보내기** — 물 위 대조 뒤에 정한다 (§7). 운동 가속을 가르려면
  자이로 융합이 필요하다. 가속 크기 문턱은 옆가속 0.2 g(크기 1.02 g) 같은 경우를 못 거른다
- **연철 왜곡·주변 자기장·온도** — 모델 밖
- **자력 측정 시각 맞추기** — 새 표본 시각은 적지만 가속과 같은 시각으로 맞추지는 않는다

### 첫 수정의 오류 넷 — 사용자 검토로 잡음 (같은 날)

| 지적 | 첫 수정 | 고침 |
|---|---|---|
| ASA 를 읽을 때 모드 | 연속 모드가 된 뒤에 읽었다. ASA 는 Fuse ROM 모드에서만 읽힌다 | 전원 차단 → Fuse ROM → 읽기 → 전원 차단 → 연속 8 Hz. 모드를 흉내 내는 가짜 칩으로 시험 |
| 사방으로 돌렸나 | 좌표축별 퍼짐 ≥ 반지름. 비스듬한 평면 32점이 중심 19.09 µT 틀린 채 통과 | 공분산 최소 고유값(가장 얇은 방향 두께) ≥ 0.10r. 방향과 상관없다. 고른 공 0.58r, 구 25% 캡 통과, 12% 캡 거절을 시험으로 확인 |
| 값이 같으면 새 측정이 없나 | 같은 값을 "새 표본 없음" 으로 보고 400 ms 뒤 무효 | 같은 값도 정상 읽기. 5초 동안 한 번도 안 바뀔 때만 멈춘 것으로 본다 (잡음 수준 미확인 — `hdg` 반복 수로 확인) |
| 두 방위 함수 기준 | 평평은 신선도, 보정은 gMagOk → 900 ms 전 자력으로 보정 방위가 숫자를 냈다 | 둘 다 magFresh() |
