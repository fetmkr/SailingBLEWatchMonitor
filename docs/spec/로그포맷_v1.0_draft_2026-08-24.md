## 우리가 바꾼 것 (v1.1)

### Type B — 쿼터니언을 뺐다. 27 → 19바이트

초안은 Type B 에 쿼터니언 4칸(8바이트)을 두고 "힐·트림·헤딩은 저장하지 않는다,
후처리에서 mount_quat 적용 후 쿼터니언으로부터 산출" 이라고 했다. 그걸 뺐다.

| | Type B | 초당 | 8시간 | 32GB |
|---|---|---|---|---|
| 초안 v1.0 | 27 B | 3,080 B | 89 MB | 2,886 시간 |
| **v1.1** | **19 B** | 2,280 B | **66 MB** | **3,898 시간** |

제일 큰 흐름이 **26%** 줄었다.

옛 파일(v1.0)은 27바이트다. 읽는 쪽은 머리글의 `ver_minor` 를 보고 고른다.
파이썬·TypeScript·펌웨어 세 파서가 다 그렇게 한다. 실측으로 확인했다.

### 대신 머리글에 힐·피치 축을 넣었다

자세를 쿼터니언으로 안 남기면 가속도 원본에서 뽑아야 하는데, 그러려면
**어느 축이 힐인지**를 알아야 한다. 보드는 그걸 NVS 에만 갖고 있었다.

우리는 실제로 힐 축을 X → Y 로 바꾸고 부호도 뒤집었다. 그 전후 파일을 같은
규칙으로 읽으면 값이 틀린다.

```
 65  U1  heel_axis    0=X 1=Y 2=Z
 66  U1  heel_sign    0=+ 1=-
 67  U1  pitch_axis
 68  U1  pitch_sign
 69  R4  heel_off     기준각 (도)
 73  R4  pitch_off
```

읽는 쪽은 이렇게 계산한다.

```
힐   = asin(heel_sign  * 그 축의 g / 중력 크기) - heel_off
피치 = asin(pitch_sign * 그 축의 g / 중력 크기) - pitch_off
```

### 세션을 닫으면서 머리글을 다시 쓴다

```
 48  U4  duration_s
 52  U4  nav_rows
 56  U4  imu_rows
 60  U4  dropped      0 이 아니면 구멍 난 세션
 64  U1  closed       1 이면 제대로 닫힘
```

기록을 시작할 때는 `utc_start` 도 세션 길이도 모른다. 전원을 켠 직후에는
GPS 가 시각조차 모른다. 그런데 나중에 **목록만 보고** 뭘 받을지 정하려면
그 값이 있어야 한다 (`TRANSFER.md` §1). 그래서 닫으면서 다시 쓴다.

### 그 밖에

- **값 없음 표식** — `sog/cog/h_acc 0xFFFF`, `lat/lon 0x80000000`,
  `itow 0xFFFFFFFF`, `week 0xFFFF`. 0 을 쓰면 "정박 중 0노트" 와 "위성 못
  잡음" 이 구별되지 않는다
- **파일 이름** — `/LOGS/SNNNNN.HLG`. 초안의 `YYYYMMDD` 는 전원을 켠 직후에
  날짜를 몰라서 못 쓴다. 시각은 머리글에 있다
- **자이로 스케일** — 1/32 °/s (±1024) 로는 BNO085 의 ±2000 °/s 를 못 담는다.
  1/16 (±2048) 로 바꿀 것을 권한다. 센서 정확도가 3.1 °/s 라 해상도 손해는
  없다 [확인: BNO08X 데이터시트 §6.6, §6.7]
- **`s_acc`(속도 정확도)** 를 Type A 에 넣을 것을 권한다. 요트에서 제일
  중요한 값이 속도인데 그게 믿을 만한지 알 방법이 없다
